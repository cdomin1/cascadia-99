# Battle Royale targeting presentation

Both clients use original amber target borders and stable server-assigned player numbers. The server adds sourceId, targetId, matchId, attackSequence and eventId to locally relevant confirmed sent/attack messages. These are metadata on existing attacks; amounts, cancellation, CPU decisions and targetFor rules are unchanged. Manual targeting highlights the chosen live opponent. Automatic modes choose at attack time, so their highlight means the last confirmed attacked opponent, not a predicted future target.

`targeting-vfx.mjs` and native `battle_targeting.gd` cap the local timeline at eight 576ms trajectories plus 96ms impacts. A monotonic per-match event sequence rejects duplicate/stale messages across reconnects. State snapshots never create trajectories. Actual source/destination board IDs resolve endpoints every frame, including resized layouts. Effects use opaque, 3px-snapped square trails, amber outgoing and red incoming. Size scales with attack amount. Reduced motion uses static dotted connections; reduced flashing keeps stable colors. Cyan is reserved in presentation configuration for a future Reversal channel; there is no Reversal combat or ability implementation.

Battle thumbnails use compact numbered layouts; native sizing fits available space and target changes scroll the selected board into view if necessary. Number/title metadata remains readable in labels and accessible names; extremely small windows can require scrolling. Only local attack events create trajectories; the other 98 boards do not animate a complete combat network. Incoming effects supplement the existing garbage queue and native incoming-count label.

Verification: shared configuration, 24 exact native/web geometry fixtures, cap/dedup/endpoint/accessibility unit tests, actual server-confirmed attack flows in both clients with one and 98 CPU opponents, target changes and existing mode regressions. Local checks are not a claim of 99-human Internet scalability or measured universal 60 FPS. See `scripts/targeting-smoke.mjs`, `godot/tests/targeting_smoke.gd` and `test/targeting-vfx.test.mjs`.
