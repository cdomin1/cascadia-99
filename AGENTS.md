# VEXELON development

Canonical identity: **Neo-Vector Arcade — “1982, BUT IMPOSSIBLE.”** Follow `docs/NEO_VECTOR_STYLE_GUIDE.md`. The old NES/pixel-art final direction and selectable themes are retired.

- Inspect current code, status and documentation before editing. Preserve user work. Both Godot and web are first-class; implement and verify equivalent behavior and presentation.
- **BLACK IS THE PLAYFIELD. LIGHT IS INFORMATION. THE BOARD IS THE HERO.** Before adding permanent UI, ask whether it is needed now, can be conveyed visually, can be contextual, or belongs in Pause/Settings.
- Kode Mono is the official UI typeface, locally bundled under `fonts/kode-mono/` and `godot/assets/fonts/kode-mono/` with OFL licenses. Use shared typography tokens and 400/500/700; preserve VEXELON and PixelNimbus brand artwork. No runtime font CDN.
- One canonical palette: `neo-vector.mjs` must match `godot/assets/neo-vector.json`. Do not restore theme/palette selectors, light mode, theme persistence, decorative grids or per-cell boxes. Use semantic colors and clear tile geometry.
- Web title keeps two zones: brand/secondary navigation and direct name/mode/CPU/difficulty/rules/Play CPUs/Create Room/Join. Valid saved settings launch CPU play with one action. Do not hide common setup behind mode/configuration pages. Native navigation remains unchanged. Audio/music selection and accessibility belong in Settings. Keep Pause available; online simulation continues while menus are open.
- Tutorial progressively reveals systems: lessons 1–4 board/goal, lesson 5 Glitch, lesson 6 Flux, lesson 7 opponent/targeting. No debug toolbar. Next follows success; controller users reach navigation through Pause. Practice tools/configuration belong in Pause; Practice has no lesson navigation.
- Keep gameplay, Phase 1 balance, authoritative countdowns, target algorithms, protocol/storage compatibility and attack deduplication unchanged. No Phase 2/Reversal/Last Stand/meta mechanics. Core gameplay lives in `engine.mjs`, `abilities.mjs`, `flux-config.mjs`, `match-rules.mjs` and server authority.
- Use player-facing Glitch Blocks / Glitch Attack / Glitch Break / GLITCH INCOMING!; retain internal garbage identifiers where necessary. Hide zero-threat warnings and inactive generic messages.
- Presentation cannot pause authoritative simulation, delay input or determine targets. Selector stays above effects. Cap particles/trajectories and dim unrelated 99P boards. 2P/4P/Teams need readable, brighter opponent boards.
- Preserve music continuity, independent audio preferences, reduced motion/flashing, shake and effect quality. Rumble is not implemented; do not claim hardware haptic support. Four existing arrangements remain prototypes; see `docs/OST_STATUS.md`.
- Keep semantic input actions, time-based repeat, dominant-axis analog arbitration, generic dynamic prompts and complete controller focus. Verify menus and gameplay using available synthetic checks; do not claim physical compatibility without testing.
- Offline training reuses the real engine. Native source builds need Node 22+ and adjacent training helper; browser offline reload needs installed service worker. Practice assistance must never enter competitive rooms or records. Restore online identity after leaving local training.
- Run `npm test`, native import and relevant browser/native fixtures. `npm run smoke:web` checks the current simplified UI; `smoke:phase1`, `smoke:targeting`, `smoke:tutorials`, `smoke:selector`, `smoke:retro` retain meaningful regression coverage. Existing historical recording assets are retained but the homepage showcase is retired.
- Use dedicated feature branches and logical verified commits. Push authorized changes and sync the local checkout. Do not automatically merge. Preserve untracked studio artwork.
- Report actual evidence and limitations: virtual layouts are not monitor certification; synthetic controllers are not physical hardware tests; 99 CPU seats are not 99-human Internet scalability; audio architecture is not a finished OST.
